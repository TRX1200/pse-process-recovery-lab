# 공정 평가와 PSE 사례 만들기

이 앱은 교육·연구용 축약 모델이다. 화면이 정교하거나 방정식이 많다는 사실만으로 실제 공정 정확도를 입증하지 않는다. 포트폴리오에서는 **요구조건을 정의하고, 이상을 관측하고, 경쟁 가설을 구분하는 실험을 설계하고, 여러 지표로 조치를 평가한 과정**을 보여준다.

Applied Materials의 공개 [Etch PSE 직무 설명](https://jobs.appliedmaterials.com/job/hillsboro/process-support-engineer-etch/95/94623970896)과 [한국 PSE 직무 설명](https://jobs.appliedmaterials.com/job/hwaseong-si/metal-packaging-process-support-engineer/95/96503109824)은 고객 요구에 맞춘 공정 최적화, 가설 실험·DOE, 통계 분석, 기술 보고, 원인 분석을 설명한다. 2026-09-28 확인한 경력 공고의 공통 역할을 참고한 것이며 사용자가 지원할 신입 공고의 요구사항을 대신하지 않는다.

## 좋은 Etch는 무엇인가

재료·패턴·막 구조와 다음 공정의 요구가 먼저다. 정해진 재료를 원하는 만큼 제거하면서 보존할 재료와 형상을 유지해야 한다. 빠른 식각, 높은 선택비, 낮은 비균일도 중 하나만으로 전체 성공을 판단할 수 없다. Applied의 [Selectra 제품 설명](https://www.appliedmaterials.com/us/en/product-library/producer-selectra-etch.html)도 불완전 제거, 선택성 부족으로 인한 치수 변화, 패턴 변형을 구분해 설명한다. 이 제품이 아래의 가상 모델과 같은 반응계를 쓴다는 뜻은 아니다.

| 평가 질문 | 현재 앱에서 볼 것 | 실제 공정에서 추가로 필요한 것 |
| --- | --- | --- |
| 원하는 양을 제거했는가? | 종점의 면적 평균 깊이와 목표 허용 구간 | 재료별 두께 계측, 단면 측정, 하부막 영향 |
| 위치에 따라 일정한가? | 가정된 방사형 분포의 깊이 비균일도 | 실제 wafer map, 패턴 밀도·종횡비 영향 |
| 보존할 재료를 지켰는가? | 마스크 손실과 정상 선택비 | 초기 마스크 두께, 하부막 손실, 실제 재료 반응 데이터 |
| 형상과 표면이 적절한가? | 현재 평가 불가 | CD, 측벽 각도, 잔사, 거칠기, 손상 계측 |
| 반복 실행해도 유지되는가? | 현재 평가 불가 | 반복 웨이퍼·챔버 데이터, 측정계 검토, 통계 평가 |
| 생산성 목표를 지켰는가? | 처리 시간 | 이송·안정화·세정·장비 가동률을 포함한 처리량 |

## 화면 사용법

1. **공정 평가 → 목표 규격 설정**에서 요구값을 정하고 `규격 적용`을 누른다. 기본 Etch 예제는 평균 깊이 30±3 nm, 비균일도 ≤5%, 마스크 손실 ≤3 nm, 정상 선택비 ≥10, 처리 시간 ≤90 s다. ALD는 입구 쪽 투영 두께 5±0.5 nm, 깊은 곳/입구 쪽 ≥95%, 중첩 ≤0.02 Pa·s, 종료 잔류 ≤0.01 Pa, 사이클 ≤6 s다. 모두 프로젝트에서 선택한 연습값이며 산업 공통 합격 기준이 아니다.
2. 레시피를 실행한다. 판정은 **마지막으로 실행한 결과의 종점**을 사용한다. 입력만 편집한 상태에서는 이전 결과를 평가한다. 재생 중간값으로 합격이 바뀌지 않는다.
3. 항목별 정의, 허용 구간, 현재 값과 다음 확인 실험을 읽는다. 비교 기준을 선택하면 그 기준의 조건·처리 시간도 그대로 사용해 같은 규격으로 평가한다.
4. **수식·원리**에서 사용한 방정식, 변수 단위와 현재 계산값을 확인한다. 표시값은 반사율·온도 등 고장이 적용된 유효 상태를 사용한다. 반올림된 숫자는 표시용이며 판정은 원래 정밀도의 값으로 수행한다.
5. **Troubleshooting → 실험 메모**에 관측, 경쟁 가설, 구분 실험, 조치와 부작용, 남은 불확실성을 쓴다. `평가 보고서 JSON`에는 평가 버전, 평가 시각, 규격, 원 실행 ID·모델 버전·파라미터·결과, 비교 기준과 메모가 포함된다.

규격은 공정별로 브라우저에 저장된다. 실행 기록의 일부로 자동 고정되는 사전등록은 아니다. 평가 시점의 규격을 보고서에 복사하므로, 실험 전후 같은 규격을 적용했는지 보고서끼리 확인한다. 규격을 완화해 합격으로 바꾼 것은 재평가이며 공정 개선이 아니다. 레시피 JSON과 기존 Run JSON은 원래 형식을 유지한다. 규격이 필요한 증빙은 별도의 평가 보고서를 사용한다.

판정은 `계산 가능한 항목 충족`, `설정 규격 미달`, `판정 보류`로 구분한다. 한 지표의 좋은 값으로 다른 항목의 미달을 상쇄하는 총점은 없다. 일부 미달과 평가 불가가 함께 있으면 미달로 표시하고 평가 불가 항목도 남긴다. 계산 범위 밖·이전 모델 버전은 판정을 보류한다. Etch 깊이 0에서 비균일도, 마스크 제거율 0에서 선택비, ALD 무성장 상태의 두께비는 합격용 0 또는 무한대로 바꾸지 않는다. 모델 가정 경고와 미계산 품질은 규격 판정과 별도로 읽는다.

## 실제로 실행한 모델 예시: 더 깊이 깎는 것이 항상 개선은 아니다

2026-09-28, `etch-ar-global-0.1.1`로 아래 사례를 실행했다. 예제 규격은 위 Etch 기본값으로 고정한다. 기준 레시피는 서버의 기본값이며 주요 값은 600 W, 20 mTorr, 100 sccm, 반응 가스 분율 0.04, 바이어스 120 V, 60 s다. 기본 RF 반사율 0.04, 결합 효율 0.75, 듀티 1을 사용한다. 아래 결과는 **결정론적 가상 실험이며 실제 웨이퍼 계측값이 아니다.**

| 사례 | 평균 깊이 nm | 마스크 손실 nm | 정상 선택비 | 비균일도 % | 시간 s | 예제 규격 평가 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 기준 레시피 | 28.8548 | 2.5948 | 11.1262 | 1.3546 | 60 | 계산 가능한 5항목 충족 |
| RF 매칭 이상, 강도 0.35 | 25.7830 | 1.4833 | 17.3965 | 1.3687 | 60 | 깊이 부족 |
| 같은 RF 이상 + 시간만 70 s | 30.0838 | 1.7306 | 17.3965 | 1.3682 | 70 | 5항목 충족, RF 이상은 여전 |
| 정상 조건 + 바이어스만 250 V | 34.8864 | 4.7632 | 7.3266 | 1.8928 | 60 | 과도한 깊이·마스크 손실·선택비 미달 |

- **Observed:** RF 이상은 실제 반사율을 0.04 → 0.376으로 높이고, 흡수 전력을 432 → 280.8 W로 낮춘다. 같은 60 s에서 깊이가 감소한다.
- **Inferred:** 같은 고장을 유지하며 시간을 70 s로 늘린 사례는 모델 안에서 깊이를 보상한다. 처리 시간은 16.7% 늘고 RF 전달 상태는 회복되지 않으므로 장비 문제 해결이라고 쓰지 않는다.
- **Observed:** 250 V 바이어스 사례는 깊이를 늘리지만 마스크 손실을 키우고 선택비를 낮춘다. 예제 규격에서 공정 개선으로 판정할 수 없다.
- **Unknown:** 실제 재료/장비에서도 같은 크기의 변화가 나타나는지, 형상·손상·잔사·반복성까지 유지되는지는 알 수 없다.

가상 고장 이름을 알고 실행한 것은 원인을 독립적으로 찾아낸 블라인드 진단이 아니다. 학습자는 예를 들어 RF 전달 이상과 반응종 공급 부족을 경쟁 가설로 놓고, 어떤 추가 관측·실험으로 둘을 구분할지 스스로 기록해야 한다. 실제 장비에서는 RF forward/reflected power와 계측 데이터 등을 확보하고, 모델이 사용한 가정을 확인해야 한다.

재현 명령:

```powershell
python sim_app/run_reference_cases.py --out outputs/process_studio/spec_review_v0_3
```

생성 JSON은 모든 기본값을 채운 파라미터와 유효 상태를 포함한다. 주요 실행 ID는 기준 `9f29c7512177`, RF 이상 `2fcf769f6d96`, 시간 보상 `c4d44090db84`, 고바이어스 `085d2ad5f1b0`이다. 참고 사례 8개/지표 73행을 생성한다. 평가 계산 자체는 프런트엔드 `assessment.ts`에서 수행하며 Python 모델의 지배방정식을 바꾸지 않는다.

## 지원서에 쓸 때

도구 제작은 준비 단계다. 위 예시를 직접 재현하고 다른 조건까지 검토한 뒤, 본인이 수행한 부분을 구분해 아래 흐름으로 기술한다.

> 축약 공정 모델에서 목표 깊이·균일도·마스크 손실·선택비를 동시에 평가하는 실험 환경을 구현했습니다. [본인이 설정한 문제]에 대해 [경쟁 가설]을 비교하고 [실험]으로 구분했습니다. [계산 결과]와 [부작용]을 확인했으며, 실제 장비 적용을 위해 필요한 [추가 데이터와 검증]을 정리했습니다.

실제 장비 운용·고객 문제 해결·물리 정확도 검증을 수행한 것처럼 확대하지 않는다. AI의 코드 구현 지원과 본인이 선택·검토한 모델, 실험 설계와 해석을 함께 설명한다.
