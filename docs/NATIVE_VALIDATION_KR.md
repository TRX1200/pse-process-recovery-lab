# Native Feature Simulator — 검증 기록

2026-10-03, Windows / Python 3.12 환경에서 수행했다. 소프트웨어 검증과 수치 민감도를 기록하며,
실제 장비·재료에 대한 검증을 의미하지 않는다.

## 2026-10-07 추가 검증

초기 ripple/scallop과 보고서 기능을 추가한 native 0.2.0에서 네이티브 19개, RF 18개, 기존 Python 41개, 프런트엔드 46개 검사가 통과했다.
작업 완료 파일이 기록된 직후 native runtime이 아직 종료 중인 상태를 완료로 보고하던 경합도 수정하고 검사를 추가했다.
평면 ripple의 해석적 초기 Rq, 무공급 형상 보존, ALD 표면 이동, 입력 해상도 제한을 확인했다.
[새 실험 안내의 수치 대조](PROJECT_REPORT_KR.md)와 [8조건 원시 요약](validation/profile_sensitivity.json)을 함께 읽는다.
작은 Rq 감소량은 격자 변경에 민감하므로 정량적 평탄화 성능이나 물리 검증으로 제시하지 않는다.
아래는 기존 기준 형상에 대한 2026-10-03 기록이며 당시 버전과 검사 개수를 유지한다.

## 실행 환경

- ViennaPS 4.6.2, ViennaLS 5.8.5, NumPy 2.5.3, SciPy 1.18.1.
- 단일 스레드, 결정적 Monte Carlo seed. 예제 입력·수치 설정·환경은 각 JSON에 포함한다.
- ViennaLS 5.9.0과의 조합은 현재 설치에서 타입 등록 import 오류가 발생했다.
  이 환경에서는 실제로 로드·계산한 5.8.5를 고정한다.

## 자동 검사

저장소 루트에서 다음 명령을 실행한다.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s native_lab/tests -v
.\.venv\Scripts\python.exe -m unittest discover -s sim_app/tests -v
cd sim_app/frontend
pnpm test
pnpm build:pages
```

- 네이티브 계층: 14개 검사 통과. 입력 유효성, 경계 형상 추출, 닫힌 void 보존,
  무공급 한계, 결정적 식각 재실행, 재료 매핑, 평면 ALD 해석해, 시간 간격 민감도,
  작업 중복 거부·중단·파일 보존, 브라우저 폴링 없는 시간 제한, HTTP 입력·origin 검사.
- 기존 Python 학습 모델: 41개 검사 통과.
- 프런트엔드: 39개 검사 통과. 이 중 3개는 네이티브 단면·축 범위·비교 구조 검사다.
- TypeScript / Pages 빌드 성공. 기존 수식 렌더러 등을 포함한 약 656 kB JavaScript 청크에
  Vite 크기 경고가 남는다. 이는 계산 정확도 검사와 별개다.

## 수치 비교

`python -m native_lab.validate_numerics`로 다시 계산할 수 있다.
수치와 원시 지표는 `sim_app/frontend/public/native/validation.json`에 있다.

| 검사 | 관측 결과 | 해석 범위 |
|---|---|---|
| 평면 ALD, 일정 입사량의 Langmuir 해석해 | 상대 오차 0.202% | 단순 평면/고정 계수의 구현 검사 |
| 피복률 dt 2 ms → 0.5 ms | 절대 오차 0.04112 → 0.00983 nm | 해당 조건에서 감소, 모든 형상의 수렴 증명 아님 |
| Etch 1 s, grid 5 → 2.5 nm | 중앙 깊이 차이 0.99% | 두 격자 비교, 관측 차이를 일반 오차 상한으로 사용하지 않음 |
| Etch seed 20261003 → 20261004 | 중앙 깊이 차이 0.60% | 두 seed 비교, 통계적 신뢰구간 아님 |
| 실제 장비 / 독립 실측 | 미검증 | 정량 공정 예측·장비 인증으로 사용하지 않음 |

평면 해석해는 `a = Γβ/Nsites`, `b = Γev/Nsites`에 대해
`θ(t) = a/(a+b) × [1−exp(−(a+b)t)]`, `h = GPC × θ`로 별도 계산한다.
이는 네이티브 피복률 적분 결과를 다시 가져와 정답으로 쓰는 검사가 아니다.

## 화면에서 확인한 동작

- 로컬 웹 UI에서 Etch 1 s 및 ALD 20 cycle 작업을 실제 Python으로 실행했다.
- 완료 결과에 맞는 단면·지표·프레임 표시, 기준 단면 겹침, 시작/끝 프레임 이동,
  저장한 실행 다시 열기, 작업 중단과 직전 완료 결과 유지 기능을 확인했다.
- 폭 350 nm / 영역 400 nm 입력을 서버가 거부하고, 기존 결과를 유지했다.
- 390 × 844 화면에서 가로 넘침이 없음을 확인했다. 정밀 단면 검토는 데스크톱 화면을 권장한다.
- 새 엔진과 기존 브라우저 학습 도구 사이의 이동을 확인했다.

위 기록은 다운로드 버튼을 통한 모든 브라우저의 파일 저장, 모든 허용 파라미터 조합,
모든 장시간 계산을 검증했다는 의미가 아니다. 작업 파일 저장은 실제 worker 테스트에서 검사했다.

## 남은 연구 및 검증

### 2026-10-07 목표 평가 / 화면 검증 추가

- `pnpm test`: 프런트엔드 64개 통과. 새 검사는 평면 이동의 정확한 거리, 정현파 Rq,
  기울어진 평활 측벽, 초기 깊이 고정 ROI, 마스크 union 제외, 결측·잘못된 목표,
  ALD 두께 0의 비율, 목표 보존과 보고서 고정을 포함한다.
- 저장된 Etch/ALD ripple·scallop의 Rq를 브라우저 측 측정 코드로 재계산하여
  원래 Python 지표와 절대 차이 `1e-6 nm` 이내임을 확인했다. 이것은 구현 간 일치이며 실측 검증이 아니다.
- `pnpm build`: 성공. 약 724 kB JavaScript 청크의 Vite 크기 경고는 남는다.
- 로컬 UI에서 목표 변경 시 원시 계산값 유지·붉은 주황색 목표선/판정 변경,
  빈 입력 시 평가 보류, Etch/ALD 각각 8개 및 평면 요철 6개 그래프를 확인했다.
- ALD ripple 40-cycle 저장 예제는 4 nm conformal 목표의 RMS 거리 약 0.09 nm,
  flat 목표는 약 5.57 nm로 표시되었다. 이들은 서로 다른 설계 목표의 비교이며 물리 정확도를 의미하지 않는다.
- UI에서 ALD ripple 10-cycle 계산을 실제 실행했다. 작업
  `ef9924f48ae0480a930622ad8840ba4f`가 완료되었고, 계산 중 목표 잠금 및 완료 후 평가 갱신을 확인했다.
  결과 SHA-256: `dafa8b63cdc59b6b671cf2fbf985e5ad6c9110951cff77c15f5ad80488af8bcc`.
- 같은 실행의 현재 평가 JSON과 SVG metadata의 평가 행이 일치했다.
  SVG에 목표선은 남고 설명용 입자는 포함되지 않았다.
- 재생/일시정지, 설명용 입자 토글 시 계산 단면 불변, 메뉴 왕복 시 목표 300 nm 보존,
  데스크톱과 390 × 844 모바일 화면을 확인했다. 해당 검사에서 콘솔 error/warn은 없었다.

이 변경은 목표와 계산 형상의 비교·시각화이며 엔진의 반응식이나 계산 계수는 수정하지 않았다.
시각적인 요철·입자 효과를 실제 장비 결함 또는 정량 플라즈마 궤적 증거로 사용하지 않는다.

### 계속 필요한 검증

- Etch/ALD 계수의 독립 실측 보정과 검증 조건 분리.
- ALD cycle bundling과 ray 수에 대한 체계적 수렴 분석.
- 반사 경계·다중 패턴·높은 종횡비에서의 수송·형상 민감도.
- 실제 마스크 재료와 선택비, ALD 반대 반응·퍼지·핵생성·온도 의존성.
- 챔버/RF/플라즈마 모델에서 feature 입구 플럭스를 구하는 연결 모델.
- 계측 불확실성·고장 진단·실험 설계 및 독립 데이터와의 비교.
